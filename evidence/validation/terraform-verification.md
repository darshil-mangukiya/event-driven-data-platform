# Terraform / AWS Target Architecture Verification

Scope: Local verification
Date: 2026-08-21/22

## Audit: What Already Existed

`infra/aws/terraform/main.tf` — real, substantive Terraform (not a stub):
KMS key, S3 lakehouse bucket, RDS PostgreSQL (encrypted, KMS-backed),
ElastiCache Redis (encrypted at rest and in transit, automatic failover),
Amazon MSK Kafka (3 brokers, KMS-encrypted), an ECS cluster, and a
CloudWatch log group. `COST_NOTES.md` already documents this is
validate-only, never applied.

**Gap**: no EKS/ECR — this platform's actual local Kubernetes work
(`deploy/kubernetes/`, `deploy/helm/cloudscale/`, live-verified against a
local `kind` verification) targets Kubernetes in production,
not ECS. The AWS target in this repository is EKS.

## What Was Added

`infra/aws/terraform/eks.tf` — an EKS cluster (private endpoint only,
KMS-encrypted secrets, matching the platform's existing KMS key), a
managed node group (2–4 nodes), the 3 standard IAM role policy
attachments a real EKS node group needs, and 7 ECR repositories — one per
locally-built service image this platform actually builds via
`docker/Dockerfile.service` (`ingestion-service`, `processing-service`,
`analytics-service`, `metadata-service`, `demo-dashboard`, `ops-console`,
`schema-registry-service`) — not an invented list. Added alongside the
existing ECS cluster (not replacing it — ECS remains a documented
alternative), consistent with "do not rebuild what already works."

## Live Verification (real, not simulated — validation only, no AWS)

```
$ cd infra/aws/terraform
$ terraform fmt -check -diff
(no output — already correctly formatted)

$ terraform init -backend=false
Terraform has been successfully initialized!

$ terraform validate
Success! The configuration is valid.
```

## What Was NOT Done — By Design

**`terraform apply` was never run.** No AWS credentials were used, no AWS
resources were provisioned, no cost was incurred. Per the explicit
instruction: "DO NOT CREATE PAID AWS INFRASTRUCTURE WITHOUT EXPLICIT USER
AUTHORIZATION... Validated Terraform is enough to unlock Terraform / AWS
architecture / Infrastructure as Code claims when correctly labeled
VALIDATED / CONFIGURATION-ONLY, not deployed."

**Status: this is a validated target architecture, not a deployed one.**
Local execution (Docker Compose, and the local environment's real kind cluster) is
the platform's actually-running form; AWS mapping (RDS/ElastiCache/MSK/
EKS/ECR/S3) is the documented, `terraform validate`-clean target for what
a managed deployment would use — never conflate the two.

The `.terraform/` provider cache directory generated by `terraform init`
was removed after validation (not committed; added to `.gitignore`
alongside `*.tfstate*`, since no state file should ever be committed
either — none was created, as no `apply` ran).
