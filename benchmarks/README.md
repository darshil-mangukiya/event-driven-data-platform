# Benchmark Evidence Workflow

This folder stores local benchmark result files generated by the load-test runner.

## Quick path

```bash
make load-test-and-compare
```

Runs a real load test against the local stack (`make up`/`docker compose up`
must already have ingestion-service running), writes a timestamped result
into `benchmarks/results/`, and immediately gates it against the checked-in
baseline (`samples/benchmarks/local_ingestion_sample.json`) with
`scripts/compare_benchmarks.py` — exits non-zero if throughput regressed
more than 20% or the failure rate got worse. This is the one-command version
of the manual steps below; previously this comparison step existed
in the repo (with its own test coverage) but had no `make` target or
documented workflow tying it to an actual load test run.

To re-compare an existing result file without re-running the load test:

```bash
make benchmark-compare
```
(uses the most recently modified file in `benchmarks/results/`.)

## Manual path

```bash
python scripts/load_test_events.py \
  --batches 50 \
  --batch-size 100 \
  --output benchmarks/results/local-ingestion-$(date +%Y%m%d%H%M%S).json

python scripts/benchmark_report.py --output docs/benchmark-evidence.md

python scripts/compare_benchmarks.py \
  --current benchmarks/results/<your-file>.json \
  --baseline samples/benchmarks/local_ingestion_sample.json \
  --pretty
```

The report intentionally distinguishes local evidence from production-scale architecture targets.

## A note on the baseline

`samples/benchmarks/local_ingestion_sample.json` was captured on one
particular machine; a slower or more contended host (a CI runner, a
constrained sandbox, a laptop under load) will legitimately show a lower
`events_per_second` without that being a real code regression. Treat a
`compare_benchmarks.py` "failed" status as a signal to inspect the numbers,
not an automatic verdict — this is why the comparator is not wired into
`make ci-local` or `.github/workflows/ci.yml` by default (see
`docs/LIMITATIONS.md` "Load Testing Scope"). Confirmed directly: a real load
test in this project's own sandbox environment measured ~352 events/s
against the checked-in baseline's ~594 events/s — a genuine machine-speed
difference, not a code regression.
